# Prompt mode

Prompt mode is an experimental beta, off by default. Enable it under Settings → Dictation → Prompt mode. Its setup action allows on-device Speech Recognition and Screen Recording. Existing dictation setup handles microphone and Accessibility access.

Prompt mode uses its own activation key, initially Right Command. Hold to speak and release to finish, or enable tap-to-toggle. Fn or your chosen normal shortcut continues ordinary dictation without screen recording. Command combinations pass through and cancel a held prompt recording.

During a prompt, hold Command and click to capture an 800 × 600 area around the pointer, clipped to its display. Hold Command and drag to choose a rectangle instead. Release the mouse to capture, or press Escape to cancel the rectangle. These gestures do not click or drag the receiving app. You can add screenshots without typing or speaking.

Each completed capture flashes its border and flies into a bottom-left thumbnail stack. The stack shows up to three rounded screenshots with a thin highlight and a soft shadow, without captions or a count label. It shrinks to a small, dimmed stack after 1.6 seconds, stays click-through, and respects Reduce Motion. Thumbnails are prepared off the main thread. The deck uses a compact window. The flying thumbnail moves in a separate, fixed-size window, so its backing buffer never expands across the display. The stationary selection window draws only four thin border layers and disables automatic layer flattening. Drag updates are coalesced to the display rate, up to 120 Hz. Captures already requested finish even if dictation stops. Cancel discards them. Spoken references appear after final timestamp matching.

While you dictate, S2T keeps a temporary local frame-and-cursor history at four samples per second. It retains the entire display under the pointer, including the desktop, menu bar, Dock and all visible windows. The display filter excludes no windows or applications. S2T verifies the filter has display scope and full display bounds before starting. System audio and the rendered cursor are excluded. Full frames use JPEG quality 0.72 in memory, with a 2400-frame and 256 MiB limit. Reaching either limit stops further frames and shows an explanation. The app's existing ten-minute dictation limit also applies.

After recording, S2T finds references such as "here", "like here", "zoom in here", "this tab here", "look at this", "check this out", "schau mal hier" and "schau dir das an" in the final transcript. It selects nearby recorded frames using word timestamps relative to the first microphone sample. AssemblyAI supplies word times. Other providers can use aligned English or German on-device Speech results from the same microphone audio. Small recognition corrections can use a time estimated between neighboring words. The app reports these estimates.

Rapid repeated references are retained separately. There is no eight-reference cap or minimum interval between final cues. Up to 64 references can be delivered in a prompt; unmatched cues and references beyond that limit produce a visible warning. S2T never fills gaps by taking screenshots after recording. Frame selection rejects samples more than 0.6 seconds from the matched word. Sampling and display-frame timing are approximate, so very fast pointer motion can still associate a nearby position.

Screenshot mentions stay inline at their spoken references. Before cleanup, S2T inserts a marker immediately after each spoken cue and tells the existing cleanup model to keep it intact beside the same words. Screenshot preparation still runs concurrently with cleanup. Before the completed text is pasted, markers become numbered screenshot mentions and unmatched markers are removed locally. There is no extra model request or alignment wait. Manual selections without a spoken cue remain attachments without adding a trailing list to the text. Screenshot-only prompts still contain their numbered mentions.

Manual crops decode and encode away from the UI thread, directly from the retained display frame. Repeated spoken references to the same frame reuse its PNG conversion. Screenshot-only prompts skip waiting for speech alignment, and saving reference files runs away from the UI thread. Accepted manual screenshots take priority within the shared 64-reference limit; omitted spoken references produce a warning.

Full display frames are transient; unselected frame history stays in memory and is discarded after selection or cancellation. Selected images become PNG files under ~/Library/Application Support/S2T/Prompt references. Each delivered reference includes its timestamp, filename and prompt-set ID. S2T does not automatically delete saved references.

When dictation finishes, S2T first attempts to attach the screenshots, then inserts the prompt text. Capturing an image does not paste it immediately. Each attachment attempt copies the selected file list in one marked clipboard transaction and sends one Command-V to the receiving app. Every screenshot also provides PNG clipboard data. The app waits 750 ms for the batch and compares bounded Accessibility attachment metadata before and after. This reads roles, geometry and attachment labels, never text-field values. If the first paste is observably absent, it checks again after text insertion before retrying once at the end. This runs after any original-input restoration and after menu dismissal. If the first attachment attempt was not sent, it can also retry after the text. Unknown or busy results are not retried automatically, avoiding duplicate attachments. Pasting is guarded by focus, permission, menu and cancellation checks. S2T does not submit the prompt.

Confirmed attachments dismiss the screenshot deck. Unconfirmed attachments leave a small dimmed stack briefly, then hide it. Final prompt text is copied only after successful delivery, without overwriting a newer clipboard copy. The receiving app must accept pasted files, and some apps expose no usable attachment metadata. Sent events alone do not prove that attachments appeared. S2T cannot control the receiving app's own attachment thumbnail layout. Prompt mode → Reference images offers the saved files and manual image copy when needed. Cancel stops pending work and clears temporary history but preserves files already saved.

On-device Speech needs the chosen English or German model installed by macOS. Audio buffering remains bounded and task rollover uses overlapping audio. Final provider timestamps can still match references if local recognition fails. Without usable timestamps, S2T reports missing references instead of guessing a capture location.

## Verification

Use `bash scripts/test.sh` and package with `bash scripts/build-app.sh`. The packaged `--verify-prompt-mode` checks Command gestures, Escape, shortcut coexistence, a rounded bottom-left stack, collapse and restart behavior, coalesced drag rendering, nonblocking recorder stop, before-text attachment confirmation and end fallback without duplicates, screenshot-only delivery, pending capture ordering/cancellation, generated timelines, twelve rapid references with distinct frames, timestamp offsets, missing-frame warnings, memory bounds, cancellation, unconditional saving, error fallback and delivery ordering. It uses isolated clipboard/storage, fake transport and synthetic audio. Hidden WebKit fixtures check full Unicode text delivery without submission. No real screen, microphone, credentials, clipboard, keyboard posting or user fields are used.

See [timeline verification](verification/prompt-timeline.md) for the controlled before/after benchmark and its limits. Actual screen-stream behavior, live provider latency and receiving-browser attachment acceptance remain unverified.
