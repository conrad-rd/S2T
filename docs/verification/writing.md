# Writing settings

Writing is a separate sidebar destination. Instructions and Dictionary share a full-height Markdown source workspace with one toolbar. The AppKit text engine styles headings, emphasis, strikethrough, lists, quotes, links, inline code and fenced code without changing the saved characters. A compact formatting menu inserts common Markdown source, with Command-B, Command-I and Command-K shortcuts. Styling is coalesced while typing and bounded to the supported 64 KB document size. The AppKit text engine also has soft wrapping, monospaced text with paragraph spacing, per-document undo/redo, and an inline native find/replace bar through the search button or Command-F. It has no ruler or line-number gutter, so editor content stays clipped below the toolbar and selection changes do not trigger a second custom paint pass. Smart quotes, dash substitution, automatic replacements and autocorrection are off to preserve exact text. The footer shows word count and save state. Reload and the disabled Marketplace item live in Document options.

Documents use `instructions.txt` and `dictionary.md`. The first read renames an older `system-prompt.txt` to `instructions.txt`, keeping its text, and never replaces an existing `instructions.txt`. Edits remain drafts until Save or Command-S. Switching documents or visiting model settings retains each editor's draft, selection, scroll position and undo history. Reload asks before discarding an unsaved draft. Saving compares the file with the last loaded version and reports external changes instead of replacing them.

Edit with AI starts collapsed below the editor. Expanding it reveals the requested-change field and a model-name button. That button opens a separate model settings screen. Provider, model, host, reasoning and speed live there; Back preserves both document drafts. Three model suggestions use dismissible Liquid Glass bubbles.

AI writing sends only the current document and requested change. It asks the model for the complete revised document as Markdown source by default, without a surrounding code fence. OpenRouter uses the saved OpenRouter key; Codex CLI uses its existing login and executable setting. Model choices and per-model reasoning/speed are saved separately from dictation. A fixed OpenRouter host disables fast routing. Codex options follow the local model catalog. Contributor consent starts off and applies only to the selected writing model.

A completed request uses the same full-size editor for review, with an Original/Suggestion switch. The original is read only; the suggestion remains editable. Apply and save replaces the document only after review, and Discard returns to the preserved draft. Cancelling, editing the source or leaving the section rejects obsolete results. Model requests do not write files or use the dictation cleanup wrapper.

## S2T credits for Writing, September 26

The AI composer has a compact native Connection picker beside its model button: Your providers or S2T credits. It applies to both Instructions and Dictionary. Writing stores its funding choice and paid model, host and per-model options separately from personal Writing choices and every dictation funding/model preference. Older saved Writing settings still decode as personal-provider settings. The existing compact model picker and arrow-cursor regions are retained. Credit-funded choices use the service's text-model catalog; OpenRouter custom IDs are available only when the service advertises catalog support. Codex and Local stay personal connections.

Both funding paths use the same `WritingDocumentRequest` contract and output validation. Paid edits use the existing `cleanup` billing operation with the document-editing system prompt and complete requested-change/document text, never the dictation-editing wrapper. S2T credentials go only to the credits service. There is no automatic fallback to a personal provider. Each submitted edit has one idempotency key, retained across network retries. Suggestions, follow-up edits, cancellation and explicit Apply & save keep the existing review semantics. Credit-account failures are also recorded under API keys, and completed/failed/cancelled requests trigger a balance refresh.

The current service caps cleanup input at 16,000 UTF-8 bytes, including the requested change and its formatting. Writing checks this before submission without truncating text. Personal-provider editing retains its 65,536-byte document and 4,096-byte request limits. The credit service's existing model/output/price ceilings still apply; incomplete output cannot become a suggestion. Submitted or incomplete inference may consume credits even if the user stops or discards the suggestion. These limits are explained in Writing model options and request errors. No Worker or dashboard deployment is required.
