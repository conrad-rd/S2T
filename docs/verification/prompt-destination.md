# Prompt destination and completion time

Both ordinary dictation and Prompt mode capture the receiving application, window, editor, selection metadata, web-area identity and selected native tab when recording finishes. Later focus changes cannot replace this destination. Text and screenshots validate the saved field before each clipboard transaction. Missing, closed, secure or inaccessible fields retain the result instead of falling through to the current application.

Delivery uses the saved application's native Paste action. S2T briefly activates the saved app, restores a minimized window and the saved tab and field, then returns to the prior foreground app when there has been no newer user input. A tab or app switch may therefore be briefly visible. Restoration respects newer user input and focus changes. Destination tracking hashes the nonsecure receiving field text in memory. It refuses restoration when the text has changed or cannot be verified, so an old selection cannot overwrite newer edits. It does not persist or upload the field text, or read screen pixels. Native tabs are found through generic Accessibility roles and selected state, without browser names or title matching.

Bottom and both input appearances use the same saved destination. Input geometry continues to follow the original field's movement and size through the existing detector. The processing animation hides when the original tab is not selected, or its destination is unavailable, instead of moving to the new website or falling back to the pointer's display.

Screenshots attach directly by default. Describe screenshots with AI remains available as an explicit option and retains the existing provider/model choices. Reference matching, timestamps, screenshot order, original PNG data, filename references and normal text cleanup remain active with descriptions off. Text now uses one native Paste operation before the image transaction, removing the previous character-by-character delay. Unconfirmed images remain on the clipboard. No automatic duplicate attachment retry is performed.

## Measurements

Existing numeric timing preferences showed the latest ordinary dictation taking 4.338 seconds, including 2.902 seconds transcription, 0.756 seconds cleanup and 0.345 seconds insertion. The last saved Prompt image-analysis duration was 5.358 seconds. These are separate saved runs, not a controlled live before/after comparison.

The identical generated two-image completion workload changed from 1.226 seconds with one vision request to 0.468 seconds with none. The mocked provider delays were fixed at 200 ms for transcription, 250 ms for cleanup and 1000 ms for image descriptions. A separate 1700-character workload measured 3.495 seconds of the former Unicode pacing versus about 1 ms to stage and invoke one injected clipboard paste. The native text path also retains its existing 250-ms receiver-settling interval. These measurements do not measure network inference, a real browser's attachment acceptance, or displayed animation latency.

`PromptDestinationProbe` uses injected AX trees and actions, fake process identities and an isolated pasteboard. It covers the Finish field differing from Start, other windows/tabs, restoration to a browsing tab with no editor, native atomic text delivery, selection metadata, changed field contents, closed/secure fields, ignored focus writes and same-process attachment races. `InputOutlineProbe` verifies original-field geometry with unrelated focus and subsequent movement. Existing generated Prompt, menu, clipboard, input and glow checks cover integration.

Apple's [Accessibility action documentation](https://developer.apple.com/documentation/applicationservices/1462091-axuielementperformaction) describes native action errors, including unsupported actions and ambiguous timeouts. Unsupported Paste actions retain the existing Unicode fallback with explicit destination validation; ambiguous failures do not trigger an automatic duplicate paste.

Live browser background delivery, focus restoration and attachment acceptance remain unverified. No real windows were manipulated, providers called, recordings made or screen pixels captured during verification. The running app is preserved.
