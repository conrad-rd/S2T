# Local Dashboard

Dashboard is the first settings destination and has a direct menu action. The page is native SwiftUI with a local usage model. It has no login, balance lookup, purchase controls or account history. It never requests account data when opened.

The app records numeric usage metadata from existing HTTP responses. `LocalUsageTransport` wraps the app's dictation, Writing and meeting transports. No extra provider requests are made. S2T-funded calls count only in S2T credits. Personal OpenRouter calls use `usage.cost` and `usage.total_tokens`. AssemblyAI calls estimate cost from audio duration and the returned model, including the speaker-label surcharge for meetings. Unsupported models and missing costs remain unknown and are excluded from totals. Pending S2T reservations are separate until a settled/released response arrives. Failed or lost responses cannot establish actual charges, and legacy streaming completions do not report a charge, so those are outside local totals.

Metadata stays in `~/Library/Application Support/S2T/local-usage.json`. It contains a hashed receipt for deduplication, dates, source, amounts, token counts, duration and estimate/pending flags. It never contains keys, account identifiers, model prompts, audio or transcripts. Writes are atomic and serialized; an unreadable file is preserved. Preview uses an in-memory ledger. History begins with this version and is not imported from an account. A pending reservation without a later response stays explicitly pending; opening Dashboard does not query a server to reconcile it.

Rates checked September 21, 2026 against [AssemblyAI pricing](https://www.assemblyai.com/pricing): Sync $0.45/hour, Universal 3.5 Pro batch $0.21/hour, Universal 2 batch $0.15/hour, speaker labels +$0.02/hour. These are estimates, not invoices or negotiated account rates. The response's actual model is documented in [Get a transcript](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/get). [OpenRouter usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting) includes usage and costs in the normal response without an extra request.

Run `bash scripts/test.sh`, `bash scripts/build-app.sh`, then the canonical executable with `--verify-dashboard`, `--verify-settings-sidebar`, `--verify-models-window`, `--verify-credits` and `--verify-build`. Dashboard verification uses synthetic receipts and a hidden native settings view to check UTC totals, separate sources, whole proportional strokes and 7, 30 and 90-day periods. The 90-day plot scrolls horizontally so its strokes keep their shape. It does not capture pixels, access real credentials or send provider requests. It does not establish pixel-level visual parity.

Verification completed with 417 passing service/domain tests, including complete API paths for direct Sync, charged-but-unusable OpenRouter cleanup, and repeated S2T-credit responses. Packaged Dashboard, sidebar, Models, credit-routing and build-identity checks passed. No live provider inference, account lookups or screen capture were used. The running app process is preserved.
