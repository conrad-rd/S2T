# Recording recovery

A finished recording is encrypted locally before provider requests begin. Pending audio, available transcription and completed credit-upload parts survive restart in `~/Library/Application Support/S2T/Recording recovery`. The key lives in the existing credentials vault. Failed, cancelled and undelivered finished recordings remain available under Last dictation → Saved recordings. Successful text delivery or a valid empty result removes the recording. Historical billing receipts retain only an encrypted completion record for service confirmation. The app no longer calls the retired streaming completion endpoint or infers a financial release from a 404; a saved receipt may already have been reconciled by the service. Sleep and normal quit stop capture and attempt to save the complete audio already recorded; failed saving refuses normal quit and keeps the in-memory copy. Forced termination, crashes and power loss can interrupt that save. Prompt-mode screenshot history is not included in the audio recovery copy.

Retry and Save recording are present under Last dictation and Needs attention even when no transcript exists. Saving exports a WAV through the native save dialog. A failed local write blocks networking and prevents a new recording from replacing the only in-memory copy until it has been saved. No Keychain prompt is allowed during recovery reads or writes. Verification injects its own storage and key.

Credit uploads use lossless WAV partitions when the original exceeds the safe request size or the service's two-minute per-request duration. Partitions prefer a quiet boundary near one minute, include every sample exactly once, and use the original sample rate. JSON uses stable field ordering and unescaped base64 slashes. Each part fits the existing 11 MB base64 and 12 MB HTTP limits. Completed part text is encrypted before submitting the next part and skipped on retry. Unknown outcomes retain the same request identity; definitive rejection can retry remaining parts with a new identity. Splitting may reduce recognition context around a boundary; it does not modify or truncate the stored recording.

Verification:

- `bash scripts/test.sh` covers synthetic five-minute audio at every gateway sample rate, exact sample reconstruction, actual request byte counts including slash-heavy base64, malformed WAV, encrypted restart recovery, failure isolation, and retry payment identities.
- Packaged `--verify-credits` includes a simulated pre-transcript failure, hidden Retry/Save menu metadata, a fresh AppState loading the same isolated encrypted file, successful retry/delivery and completed recovery state.
- Packaged `--verify-build` checks compiled and packaged identity.

No screen capture, microphone access, real Keychain items, real clipboard or paid requests are used. Updating the bundle does not restart an existing S2T process, whose pre-update recording may still exist only in memory.
