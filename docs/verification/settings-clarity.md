# Settings clarity

The settings toolbar follows the supplied macOS Accessibility reference. Its title uses SwiftUI `.title` in an unbordered native toolbar item; only the icon actions receive AppKit's shared glass background. The title and ordinary content use a 24-point left inset. API keys uses native grouped form sections, and model choices use native group boxes with small headings. Appearance retains its full-pane preview and floating controls. Its top toolbar uses a standard checkmark `NSToolbarItem` and an expanded, single-selection `NSToolbarItemGroup` for Still, Speaking and Processing. AppKit owns their views, dimensions and interaction effects, without custom drawing or animation. `--verify-settings-top-bar` checks every preview state, selection persistence, saved-appearance isolation and return navigation in a hidden window. It does not visually verify the press-and-hold animation. Instructions and Dictionary retain their existing document toolbar without an added page title. The same probe checks title separation, measured alignment, icon actions and navigation. Apple documents the informational-item behavior in [Build an AppKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/310/).

The standard settings pages use AppKit's expanded toolbar spacing so the title and actions sit over 30 points below the window's top edge. AppKit reserves a 73-point top safe area for the content. Writing retains its unified document toolbar. The toolbar check measures both title and action bounds after page changes, including a return from Writing and Dashboard.

Build 825 passed the packaged toolbar, Appearance window, Writing, API keys, Models window, sidebar and build-identity checks on September 23. These used hidden windows and synthetic state, with no screen capture. The full domain test command was blocked at compilation by existing `DictionaryTests.swift` calls supplying `insertionSelection`, which the current `DictionaryObservation` initializer does not accept. This interface change does not alter either dictionary file.

Dashboard amounts register the bundled `bitcount-regular.ttf` and request its actual PostScript name, `BitcountPropSingle-Regular`. The previous `Bitcount` name fell back to the system font. Amount precision and dimmed fractional digits remain intact.

API keys have one inline editor per provider. Return, focus loss, page navigation and window deactivation commit a draft. Empty or whitespace-only drafts clear that account. Escape masks the value and retains the unapplied draft. Recording blocks commits while allowing drafts. The credential vault stores an empty value so a legacy Keychain entry cannot restore the removed key. No Keychain item or unrelated credential is deleted. S2T removal also disconnects the saved credits connection and clears its balance. Pending validation cannot restore a removed key.

Models puts Choose models above the comparison. Comparison controls explain their purpose; scoring methodology and missing measurements remain in native popovers. Ranking calculations and provider/model configuration are unchanged.

Instructions uses an AppKit NSToolbar with native bordered actions, document selection, formatting and document menus. It appears only on the Instructions/Dictionary page. The document keeps Find, formatting shortcuts, Command-S, draft review and reload confirmation.

Meetings opens on the recording library. Audio and model setup live in Recording options. Transcript actions share one compact row; speaker editing is available from its options menu. Dictation uses a native grouped SwiftUI Form. Prompt mode, Clipboard context, Input detection and Advanced are visible sections alongside Microphone, Shortcut and Text. Remembered clipboard items appear directly in their section. Missing permissions and failures remain visible. Existing recording, recovery, preset and shortcut actions remain reachable.

Settings no longer use collapsible section rows. Models shows its comparison and model options directly, including task-specific advanced settings. Dashboard shows recent activity directly. Writing uses a native Edit with AI switch to reveal its optional composer while preserving the document workspace. Value-selection menus and navigation actions keep their existing behavior.
